# 知返 · 个人交易与学习空间

在 [LuxAlgo Trade Journal](https://github.com/LuxAlgo/trade-journal) 基础上扩展，保留原有交易计算、导入、账户、统计图表与暗色界面，增加交易学习、图片案例、结构化复盘和日记。采用本地 SQLite 保存数据；当前交付为本机运行版本。

## 启动

Windows 下双击 `start-zhifan.cmd`，然后打开 <http://127.0.0.1:3000>。运行时保留终端窗口，按 Ctrl+C 停止。

首次启动需要网络和已安装的 Node.js/npm。脚本通过 npx 使用固定的 Node 22.16.0、pnpm 11.0.8，不替换系统 Node。首次会安装依赖并构建，后续直接启动现有构建。

修改源码后，先停止正在运行的应用，再在仓库目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-zhifan.ps1 -Rebuild
```

3000 端口被占用时可加 `-Port 3001`。脚本仅监听本机地址。没有配置云端发布或公网访问。

Windows 使用 `next start` 运行生产构建，避免独立部署打包对符号链接权限的要求；其他系统保留上游的 standalone 构建。

## 建议使用顺序

1. **交易账户**：先建立手动账户，或者使用原项目支持的导入/券商连接。
2. **交易记录**：录入成交或导入历史数据。详情保留进出场时间、价格、数量、费用、净盈亏、止损、目标价、计划盈亏比和实际 R 等原有字段。盈亏比需要填写有效的止损及目标价；它与实际收益率是不同指标。
3. **交易复盘与学习**：在交易详情记录进场理由、出场理由、做得好与下次改进、情绪、是否按计划执行；可补充正文和图片。保存后标记该交易已复盘。
4. **交易学习**：建立知识点，写理解、适用条件、失效条件和待验证的问题，设置分类、标签、状态及来源链接。可按文字、分类和状态筛选。
5. **案例库**：在知识点下添加成功、失败或待观察案例，填写标的与周期并上传截图。也可在交易详情选择知识点，将交易收入案例库，同时复制交易附件和复盘附件。
6. **日记**：记录当日学习与生活、心情和想法，按需关联知识点及实际交易。不另设读书笔记或随想模块。

知识点、案例、日记与复盘正文采用明确的保存按钮。新记录先保存一次，再上传图片；附件上传/删除会立即保存。正文支持 Markdown，可把附件插入正文并编辑图片说明。多标签页编辑同一条记录发生冲突时，系统拒绝旧版本覆盖；请先复制尚未保存的文字再刷新。

图片支持点击选择、拖拽或粘贴；PNG、JPEG、WebP、PDF，每个文件最多 8 MB。点击缩略图放大，方向键切换。删除知识点会同时删除其案例和附件，操作前会要求确认。

## 数据与备份

默认数据位于 `apps/web/data/journal.db`，图片也保存在数据库中。设置 `JOURNAL_DATA_DIR` 可指定其他数据目录。数据库、密钥、测试数据均不纳入 Git。

在侧栏 **数据备份** 中：

- **学习与日记备份 JSON**：包含知识点、案例、日记、结构化复盘及其附件；恢复采用合并方式，同 ID 记录不覆盖，重复导入不会重复添加。它不包含账户、原始成交或交易本身的附件。缺少对应交易时，会移除无效交易关联并跳过该交易的复盘，界面报告数量。JSON 导入上限 64 MB。
- **完整数据库备份**：下载一致的 SQLite 数据库，包含原项目交易数据、学习资料和图片。数据较大时使用此方式。

完整恢复步骤：

1. 先停止应用，并另外保留当前整个数据目录的副本。
2. 将下载的 `.db` 文件复制到实际数据目录，命名为 `journal.db`，替换旧数据库。
3. 确保应用已停止后，移走该目录旧的 `journal.db-wal`、`journal.db-shm`（如存在），避免旧日志影响恢复。
4. 迁移到另一台电脑时，还需保存数据目录中的 `.secret`，或原来的 `JOURNAL_SECRET` 环境变量。它用于解密券商等已保存凭据，数据库下载不包含这个独立密钥文件。
5. 重新启动应用并核对记录。

不依赖浏览器 localStorage 保存这些记录；关闭或刷新页面后，已保存的数据仍在。

开发分支为 `feat/zhifan-workspace`，`upstream` 指向 LuxAlgo 原项目；没有向上游推送。保留原项目 MIT 许可证及品牌归属说明，知返不是 LuxAlgo 官方产品。
